# 银行贷款申请与审批系统 — 技术方案文档

## 1. 系统架构设计

系统采用经典的前后端分离架构：

```
┌─────────────────────────────────────┐
│  前端层（Vue 3 + Vite + Element Plus） │
│  客户门户 / 审批工作台 / 管理后台       │
└──────────────┬──────────────────────┘
               │ HTTP / RESTful API
┌──────────────▼──────────────────────┐
│  网关/反向代理（可选 Nginx）            │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│  后端层（Spring Boot 2.7 + MyBatis-Plus）│
│  Controller → Service → Mapper/Entity │
│  Spring Security + JWT + RBAC        │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│  数据层（SQLite 文件数据库）            │
│  schema.sql / data.sql 初始化          │
└─────────────────────────────────────┘
```

- **前端**：Vue 3 单页应用，按角色展示不同视图，使用 Axios 调用后端接口，Vuex 管理用户状态。
- **后端**：Spring Boot 提供 RESTful API，Spring Security 负责认证与鉴权，MyBatis-Plus 完成 ORM 与分页。
- **数据库**：SQLite 轻量级文件数据库，适合演示与中小型场景；表结构由 `schema.sql` 初始化，初始数据由 `data.sql` 初始化。

## 4. 接口设计说明

### 4.1 通用返回结构

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

- `code`：业务码，200 为成功，其他为异常。
- `msg`：提示信息。
- `data`：业务数据。

### 4.2 主要接口列表

| 接口路径 | 方法 | 说明 | 主要参数 | 返回值 |
|---|---|---|---|---|
| `/api/auth/login` | POST | 用户登录 | `username`, `password` | token、用户信息 |
| `/api/menu` | GET | 获取当前用户菜单 | - | 菜单列表 |
| `/api/products` | GET | 查询产品列表 | `status` | 产品列表 |

### 4.3 新增/变更接口说明

- **受控文件下载**：新增 `GET /api/download/{filename}`，认证用户可下载上传目录中已保存的文件。文件名必须为 `32 位 UUID.扩展名` 格式；客户角色仅能下载与本人申请材料关联的文件，其他角色可下载其业务范围内的材料。
- **信用评估接口权限调整**：`POST /api/credit-evaluations/{applicationId}` 仅允许 `MANAGER`/`ADMIN` 执行；`GET /api/credit-evaluations/{applicationId}` 对客户开放，但 Service 层会校验该申请是否属于当前客户，防止越权查看他人评估结果。
- **申请详情接口权限调整**：`GET /api/applications/{id}` 对多角色开放，客户访问时会传入当前 `customer_id` 进行数据级过滤；`GET /api/applications/{id}/detail` 仅面向经理、审批人及管理后台。
- **合同详情接口权限调整**：`GET /api/contracts/{applicationId}` 对客户开放，Service 层校验合同所属申请的 `customer_id`；`POST /api/contracts/sign/{contractId}` 仅客户本人可调用，防止非本人签署。

## 5. 安全设计

### 5.1 JWT 认证
- 用户登录成功后，后端使用 JJWT 生成 JWT Token，携带 `userId`、`username`、`role`。
- 后续请求在 `Authorization: Bearer <token>` 头部携带 Token。
- `JwtAuthenticationFilter` 拦截所有请求，解析 Token 并将用户身份注入 Spring Security 上下文。
- Token 有效期 2 小时，由服务端密钥签名，防止篡改。
- **JWT 密钥外部化配置**：`jwt.secret` 通过 `application.yml` 注入（如 `jwt.secret: kZAE93bUKfaJLNQNF1hxJoRufLr72D8j`），`JwtConfig` 在构造时校验密钥长度必须 ≥32 位，不足则启动失败，避免使用默认弱密钥。

### 5.2 RBAC 鉴权
- 角色编码：`customer`、`manager`、`approver_level1`、`approver_level2`、`approver_committee`、`disbursement_officer`、`admin`。
- 接口通过 `@PreAuthorize("hasRole('ADMIN')")` 等注解控制访问权限。
- Spring Security 配置类中，`/api/auth/**` 允许匿名访问，其余接口需认证。

### 5.3 密码加密
- 使用 `BCryptPasswordEncoder` 对用户密码进行单向哈希。
- 数据库中存储的是 BCrypt 密文，登录时通过 `matches` 校验。
- `data.sql` 中的初始密码均为同一 BCrypt 密文，对应明文可统一配置。

### 5.4 越权防护
- 客户视角接口（如 `/api/applications/my`）从 Token 解析当前 `userId`，查询时限制 `customer_id`。
- 关键操作（签署合同、查看详情）校验当前用户是否为申请关联客户。

### 5.5 敏感数据加密存储
- 采用 AES-GCM 算法对手机号、身份证号、银行卡号等敏感字段进行加密存储，密钥 `encryption.aes-key` 同样通过 `application.yml` 外部化配置，长度校验 ≥32 位。
- 加密工具 `AesUtil` 每次生成随机 12 字节 IV，与密文拼接后 Base64 编码存储；解密时拆分 IV 与密文，保证机密性与完整性。
- 接口返回时，对敏感字段进行脱敏处理（如身份证号显示前 6 位与后 4 位，中间以 `*` 替代）。

### 5.6 文件上传安全
- **扩展名与白名单校验**：仅允许 `jpg`、`jpeg`、`png`、`pdf`，并校验 `Content-Type` 是否在白名单内。
- **文件头魔数校验**：读取文件前若干字节，与 JPEG（`FF D8 FF`）、PNG（`89 50 4E 47 0D 0A 1A 0A`）、PDF（`25 50 44 46 2D`）标准魔数比对，防止伪造扩展名或 Content-Type 上传恶意文件。
- **UUID 重命名**：上传文件保存时统一使用 32 位 UUID 作为文件名，去除原始文件名中的特殊字符，避免路径遍历与脚本执行风险。
- **受控下载接口**：`GET /api/download/{filename}` 要求认证，且仅允许访问 `uploads` 目录下符合命名规则（`^[a-fA-F0-9]{32}\.(jpg|jpeg|png|pdf)$`）的文件；客户角色只能下载本人申请材料关联的文件。

### 5.7 数据级权限校验
- 除 URL 级 RBAC 外，在 Service 层对关键资源进行用户归属校验：
  - 客户补充材料、查看申请详情/合同/评估时，校验 `customer_id` 是否匹配。
  - 客户经理、审批人、放款操作员等角色通过角色编码限制可操作的功能范围。
- 下载接口通过 `ApplicationMaterial` 关联到 `LoanApplication`，再校验当前用户是否为该申请的客户，防止横向越权下载他人文件。

### 5.8 异常处理
- 统一异常处理器 `GlobalExceptionHandler` 捕获 `AccessDeniedException`、`AuthenticationException`、`RuntimeException` 及通用 `Exception`。
- 生产环境（`app.debug=false`）统一返回模糊错误提示“系统繁忙，请稍后重试”，避免泄露内部堆栈、SQL、类路径等信息。
- 详细异常堆栈统一记录到服务端日志，便于运维排查；开发测试环境可通过 `app.debug=true` 临时开启详细错误返回。

## 6. 部署说明

### 6.1 环境要求
- JDK 1.8+
- Maven 3.6+
- Node.js 16+（前端构建）

### 6.2 后端部署

```bash
cd backend
mvn clean package
java -jar target/loan-system-backend-1.0.0.jar
```

- 默认端口 `8080`。
- 首次启动会执行 `schema.sql` 与 `data.sql` 初始化 SQLite 数据库（`loan_system.db`）。
- 生产环境建议关闭 `spring.sql.init.mode=always`，或改为 `never` 避免重复初始化。

### 6.3 前端部署

```bash
cd frontend
npm install
npm run build
```

- 构建产物位于 `frontend/dist`。
- 使用 Nginx 托管 `dist` 目录，并将 `/api` 反向代理到后端 `http://localhost:8080`。

### 6.4 Nginx 示例配置

```nginx
server {
    listen 80;
    server_name localhost;

    location / {
        root /path/to/frontend/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 6.5 测试环境
- 测试使用 `test` profile，SQLite 内存数据库，Hikari 连接池大小限制为 1。
- 测试配置位于 `backend/src/test/resources/application-test.yml`。
- 运行测试：`mvn test`。
