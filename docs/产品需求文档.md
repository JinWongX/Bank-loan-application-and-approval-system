# 银行贷款申请与审批系统 — 产品需求文档

## 1. 系统概述

本系统是一套面向银行（或类金融机构）的线上贷款业务管理平台，覆盖贷款产品发布、客户在线申请、自动信用评估、客户经理尽职调查、多级审批、合同生成、放款管理、还款计划生成及统计报表等完整业务流程。系统采用前后端分离架构，前端使用 Vue 3，后端使用 Spring Boot + SQLite，支持角色化权限管理（RBAC）与 JWT 无状态认证。

系统目标：
- 为客户（借款人）提供在线申请、材料上传、合同签署、放款查询等自助服务。
- 为银行内部人员（客户经理、审批人、放款员、管理员）提供标准化、可追溯的信贷作业流程。
- 通过规则化信用评分和多级审批流控制信贷风险。

## 2. 功能需求

### 2.1 贷款产品管理
- 管理员可新增、编辑、停用/启用贷款产品。
- 产品属性包括：产品名称、类型、最低/最高额度、年化利率、最短/最长期限、还款方式、准入条件、状态。
- 产品状态控制前端是否展示及客户是否可申请。
- 校验规则：最低额度 ≤ 最高额度，最短期限 ≤ 最长期限，利率与还款方式必填。

### 2.2 在线申请
- 客户登录后选择产品并填写申请信息：申请金额、期限、用途、还款来源。
- 系统校验申请金额与期限是否在产品的可用范围内。
- 支持上传申请材料（身份证、收入证明、经营材料等）。
- 提交后自动生成申请编号并进入信用评估环节。

### 2.3 信用评估
- 根据申请人的年龄、月收入、征信状态、负债率等指标自动计算信用评分。
- 评分等级：A（优秀）、B（良好）、C（一般）、D（较差）。
- 给出评估建议，如“建议放款”“建议正常审批”“建议补充材料或担保”“建议拒绝”。
- 评估结果持久化并驱动后续审批策略。

### 2.4 尽职调查
- 客户经理领取待调查申请，填写经营情况、资产负债、还款能力、调查结论。
- 支持上传尽调附件。
- 尽调完成后，申请进入审批环节。

### 2.5 多级审批
- 根据申请金额自动确定审批层级：
  - ≤ 50 万：一级审批人审批。
  - 50 万 < 金额 ≤ 100 万：一级 + 二级审批人审批。
  - > 100 万：一级 + 二级 + 审批委员会审批。
- 审批动作包括：通过、驳回、退回补充。
- 通过且到达最高层级后自动生成合同；驳回后流程结束；退回补充后返回客户经理补充材料。

### 2.6 合同生成
- 审批通过后自动生成电子贷款合同，包含金额、期限、利率、还款方式、违约责任等条款。
- 客户可查看合同并进行电子签署。
- 签署后进入放款待办。

### 2.7 放款管理
- 放款员在合同签署后为通过审批的申请办理放款。
- 记录放款时间、金额、收款账户、开户行、经办人。
- 放款成功后生成还款计划。

### 2.8 统计报表
- 管理员/管理层可查看数据看板：申请总量、审批通过/拒绝数量、放款金额、待办数量等。
- 支持按产品、客户经理、时间维度统计。
- 支持导出 Excel 报表。

### 2.9 用户权限
- 角色：客户、客户经理、一级审批人、二级审批人、审批委员会、放款员、管理员。
- 每个角色对应独立的菜单与操作权限。
- 管理员可维护用户信息、重置密码等。

## 3. 业务流程图（文字描述）

```
客户登录
  │
  ▼
选择贷款产品并提交申请 ──> 上传材料
  │
  ▼
系统自动信用评估
  │
  ▼
客户经理尽职调查 ──> 退回补充（如需）
  │
  ▼
进入多级审批流程
  │
  ├─ 驳回 ──> 流程结束
  ├─ 退回补充 ──> 客户经理补充材料
  └─ 通过（到达最高层级）
       │
       ▼
  自动生成合同
       │
       ▼
  客户签署合同
       │
       ▼
  放款员放款
       │
       ▼
  生成还款计划
       │
       ▼
  客户按期还款 / 查询还款计划
```

## 4. 用户场景

| 用户角色 | 典型场景 |
|---|---|
| 客户 | 登录后浏览可申请的贷款产品，提交贷款申请并上传收入证明，查看审批进度、签署电子合同、查看还款计划。 |
| 客户经理 | 领取待尽调申请，电话/现场核实客户信息，填写尽调报告并上传附件；如材料不足，退回补充。 |
| 一级审批人 | 查看 ≤ 50 万或更高级别流程中当前层级的待审批申请，做出通过/驳回/退回补充决定。 |
| 二级审批人 | 处理 50–100 万区间到达二级审批节点的申请。 |
| 审批委员会 | 处理 > 100 万元的大额贷款最终审批。 |
| 放款员 | 查看已签署合同的待放款申请，录入放款账户信息并执行放款。 |
| 管理员 | 维护贷款产品、查看统计报表、管理用户与角色权限。 |

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 普通接口响应时间 ≤ 500ms；统计报表接口 ≤ 2s。 |
| 可用性 | 系统 7×24 可运行，核心业务操作支持事务回滚。 |
| 安全性 | 密码 BCrypt 加密；接口使用 JWT 鉴权；角色权限隔离；防止越权访问。 |
| 可扩展性 | 前后端分离，业务模块按职责划分，便于后续接入征信、短信、电子签章等外部服务。 |
| 可维护性 | 代码遵循 RESTful 风格，数据库表结构清晰，关键业务状态流转可配置。 |
| 数据一致性 | 信用评估、审批、合同生成、放款等关键环节使用数据库事务。 |
| 兼容性 | 后端基于 Java 8+/Spring Boot 2.7，前端基于 Vue 3，可在主流浏览器运行。 |
